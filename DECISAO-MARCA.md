# Decisão de marca — Kilo × Passaporte Fiscal

**Status:** provisória (para confirmar com o fundador) · **Data:** 7 set 2026

## O problema

Há duas identidades vivas nos artefatos do projeto:

- **Kilo** — prancha de marca (âmbar #A8690C, Fraunces + IBM Plex Mono), conceito "registro e
  peso de créditos fiscais", repo `comeca-ai/kilo`, e-mail `pesar@kilo.ia.br`.
- **Passaporte Fiscal** — o app efetivamente construído e a metáfora de toda a Especificação
  v1.0 (passaporte, rating, verificação, "o Passaporte é o produto e o contrato").

## Decisão provisória

**Kilo é a marca-guarda-chuva. Passaporte Fiscal é o produto P1. Rede de Créditos é o produto P2.**

- Empresa/plataforma: **Kilo** (domínio, landing, e-mail, repo).
- Produto 1: **Kilo · Passaporte Fiscal** — o artefato assinado continua se chamando
  "Passaporte Fiscal" (a metáfora da spec não muda).
- Produto 2 (futuro, pós-Gate 0): **Kilo · Rede de Créditos**.

## Sistema visual harmonizado

| Token | Valor | Uso |
|-------|-------|-----|
| Fundo tinta | `#0B0F1A` | Seções escuras, app |
| Papel | `#F5EFE0` | Seções claras, cards de resultado |
| Âmbar (sobre escuro) | `#E8B53A` | Acento, CTA, destaques |
| Âmbar (sobre claro) | `#A8690C` | Acento da prancha Kilo em fundo papel |
| Verde ok | `#5BC48A` | Verificações, estados válidos |
| Vermelho alerta | `#E36A5C` | Falhas, rating C |
| Display | Fraunces (400/600/900) | Headlines, números grandes |
| Mono | IBM Plex Mono | Labels, eyebrows, hashes, dados |
| Corpo | Stack do sistema | Texto corrido |

Racional: as duas paletas já eram primas (âmbar sobre escuro); a fusão preserva o investimento
visual do app (que funciona) e o nome/domínio da prancha (Kilo).

## O que depende desta decisão

1. Landing pública (trilho 1) — já sai como "Kilo · Passaporte Fiscal".
2. Documentos futuros: spec v1.1 deve mencionar a marca-guarda-chuva.
3. Se o fundador decidir o contrário, o custo de reversão hoje é baixo (1 landing + tokens CSS).
